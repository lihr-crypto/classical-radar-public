# ADR-0003 — 跨源重复复核（只提示、人工决定、可撤销，不合并）

日期：2026-11-09。状态：采纳（HANDOFF「下一轮任务」第 4 项；动手前经评审，评审意见已并入下表）。依据：[02_SOURCES](../handoff-v1.5/02_SOURCES.md) 要求跨来源去重；[ADR-0001](0001-p1-first-slice-decisions.md) 要求“歧义时保守，宁可多一条待复核也不错误合并”。

## 要解决的问题

同一场演出常被两个来源同时登记（例如 Japan Arts 与神奈川艺术协会）。两条记录各有自己的 `concert`（身份是 `来源|URL`），都可以被确认，发现页会出两张卡。原来只有一个离线证据脚本（`parsers.possible_duplicates`），没有任何流程读它。

## 决定

| 议题 | 决定 | 理由 / 后果 |
|---|---|---|
| 提示（hint） | `duplicates.hints_for`：两条**不同来源**的公演，各有一场**未来、精确到日**的场次，**同一天**且**场馆兼容**。待确认队列的每一项多一个 `possible_duplicates` 列表 | 只指给人看，不改任何数据 |
| 场馆兼容 | 沿用 `_venue_key`：相等（任意长度）算 `venue_exact`；一方是另一方的前缀且**较短一方至少 3 个字**算 `venue_prefix` | 原脚本的前缀规则太松（短标签可匹配任何长名）；2 字场馆（如“王子”）完全相同仍然算 |
| 理由与强度 | `reasons` 列出依据：同一天、场馆、共同艺人（`shared_artists`）、标题互相包含（规范化后较短者 ≥4 字且被包含）。有共同艺人或标题包含为 `strong`，否则 `weak`（只有同日同馆） | 让人一眼看出为什么被怀疑；`weak` 不假装确定 |
| 人工决定 | 表 `duplicate_review`（不在 03_CONTRACTS，是流程暂存表，和 `import_candidate` 同类）。`PUT /review/duplicates`：`duplicate_of`（“这条和那条是同一场”）或 `different`（“不是同一场”，成对只存一条，之后不再提示）。`DELETE /review/duplicates/{a}/{b}` 撤销 | 决定可逆；两条原始记录与证据都保留，什么都不合并、不删除 |
| `duplicate_of` 的效果 | 该条（必须是 `needs_review`）**离开待确认队列**，进入 `marked_duplicates` 列表（带“撤销”）；`confirm_stored` 与 URL 导入确认都**拒绝**它（“undo that decision first”）。留下的那条正常确认 | 从源头避免发现页出两张卡；不新增“已合并”状态，不改变发现页逻辑 |
| 结构只许一层 | 被隐藏的条目指向一个可见的留存条目；留存条目本身不能被隐藏，也不能指向别人；换留存对象会替换旧选择；一个留存条目可以有多个重复条目 | 评审指出：只防 2 环会让 A→B、B→C、C→A 把三张都藏掉；一层结构下环和链都不可能 |
| 决定会过期 | `duplicate_of` 只在**原来的匹配仍成立**时生效（`effective_duplicate_of`）。再同步后日期或场馆变了、留存条目被取消或已过期，该条自动回到待确认队列并可被确认；新决定前会清掉涉及这两条的过期决定 | 评审指出：决定不能比做决定的理由活得更久，否则条目会永久卡在隐藏状态 |
| 不绕过队列 | 唯一能把 `needs_review` 升为 `official_confirmed` 的两处（`confirm_stored`、`ingest` 带确认的重导入）都做了检查；`duplicate_review` 外键 `ON DELETE CASCADE`，库里没有任何删除 `concert` 的代码 | 评审要求：要么堵住所有路径，要么在 ADR 说明不存在这样的路径 |
| 界面 | 待确认页每张卡下方显示虚线提示块（标签“很可能重复/可能重复”、对方标题与来源链接、理由、两个按钮“同一场，隐藏这条”“不是同一场”）；页面底部折叠区“已标为重复 N”，每行有“撤销”。与队列相同的 `source_id` 过滤 | 见预览截图（本次会话） |

## 没做（以及为什么）

- **已经都确认的两张卡**：发现页仍然会出两张。目前没有“隐藏已确认卡”的状态，也没有按“同一场”分组展示的设计；只有 `needs_review` 的一条能被标成重复。所以第 4 项只算“重复复核接进了确认流程”，**不是“发现页已去重”**。要做的话需要先定：哪个来源是主卡、被合并的来源怎样展示、日历/Pickup/提醒如何归属。
- **自动合并或自动判定**：不做（ADR-0001）。`weak` 提示尤其不能当作结论。
- **URL 导入暂存区里的候选**（`import_candidate`）：还没有入库成 `concert`，不带提示；导入确认后若落在已隐藏的条目上会被拒绝。
- 不改 `parsers.possible_duplicates` 和证据文件（仍用于 `check_p02_evidence.py`）。
- 标题只做“包含”判断，不做模糊匹配。
