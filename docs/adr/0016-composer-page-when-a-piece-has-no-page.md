# ADR-0016 — 曲目没有自己的 Apple 页面时，按钮改指作曲家页（并标明）

日期：2026-11-17。**状态：已被 ADR-0019 取代（2026-11-19）——没有自己页面的曲目现在改去 Apple 的搜索页，不再去作曲家页。**下面是当时的记录。采纳并实现，在未合并的分支 `ui/composer-page-fallback` 上（叠在 PR #30 上，#30 叠在 #29 上，三者都等用户说“合并”）。起因：ADR-0015 之后，曲目页按演出次数只有 37% 有按钮；我把“没有曲目页时放一个作曲家页按钮”作为可选项给了用户，用户答“可以放一个”。

## 决定

| 问题 | 决定 |
|---|---|
| 什么时候出现 | 只在**曲目页**，且这首曲子在对照表里**没有自己的 Apple 作品页**、但它的作曲家在表里有 Apple 作曲家页。曲子有自己的页面时照旧直达曲目页；作曲家也不在表里时照旧没有按钮 |
| 怎么标明 | 按钮是 `Apple Music Classical｜作曲家页`（虚线边框，右边小字“作曲家页”），下面一行：“这首曲子在 Apple Music Classical 没有单独的页面，先打开作曲家「○○」的页面，在里面找。”直达曲目页的按钮仍是实线、一行说明不变，所以不会把作曲家页当成曲目页 |
| 地址从哪来 | 还是 `classicalHref("composer", …)`：固定主机 `https://classical.music.apple.com/jp/artist/<数字 id>`，id 的形状检查不变；没有新的拼地址的地方。纯函数 `classicalWorkLink(workIds, composerIds, table)` 放在 `<browse-rules>` 里（`web/app.js`），先试曲目 id，不行再试作曲家 id；曲目的几个 id 对到两个不同的页面 → 没有曲目链接，但作曲家页仍然对，所以走作曲家页；作曲家的几个 id 对到两个页面 → 没有链接 |
| 作曲家 id 从哪来 | 和作曲家页自己的按钮同一套：这一页的作曲家 id，加上并入这一页的每一行节目的本地作曲家 id（`classicalIds("composer", ent.cid, …)`） |
| 只对曲目 | 指挥 / 演奏家页没有这个退路（他们要么有自己的页面，要么没有） |

## 风险检查

- 作曲家页的 id 和作曲家页自己的按钮是同一张表，这一步不增加新的“连错页”的可能。
- 没有 composer_key、按名字查到的 30 位作曲家（25 位逐个对过 Apple 页面标题 + 出生年，5 位名字和 Apple 标题完全一样自动通过：三善晃 1933、ハンス・ロット 1858、ジョン・アダムズ 1947、尾高惇忠 1944、湯浅譲二 1929；括号里的出生年是 Apple 页面给的，都和这几位作曲家对得上。ジョン・アダムズ 的 id 285089 是 1947 年生的约翰·亚当斯（《快速机器里的短途旅行》的作曲者），不是 1953 年生的约翰·卢瑟·亚当斯）：ブルッフ、スッペ、ペルト、マルティヌー、レハール、カゼッラ、グノー、シマノフスキ、テレマン、ドホナーニ、フンメル、ラモー、ステンハンマル、アイネム、アッテルベリ、エロール、クレンゲル、グリエール、タイユフェール、タルティーニ、ハンス・ロット、フンパーディンク、ポンキエッリ、ラウタヴァーラ、リゲティ、J.シュトラウスII世、三善晃、尾高惇忠、湯浅譲二、ジョン・アダムズ）：没有一个是“光一个姓就可能指两个作曲家”的写法。シュトラウス家只有 `j-strauss-ii`、`r-strauss`、`josef-strauss` 三个明确的 key，光写“シュトラウス”的不在表里，所以没有按钮（ADR-0014 记的 Strauss 缺口，没变）。
- 作曲家页只是“这位作曲家的页面”，不保证这首曲子就在页面里；所以按钮标明是作曲家页，说明文字写“在里面找”，不装成曲目页。
- `J.シュトラウスII世`（按名字查到）和 `j-strauss-ii`（别名表的 key）在表里指向同一个 Apple 页面（914054，ヨハン・シュトラウス 2世），所以两种写法的曲目页给出同一个作曲家页；它们在页面里仍是两项（ADR-0014 记的缺口，没变）。

## 结果（按 2026-11-17 的数据，演出次数加权）

| 曲目页 | 项数 | 演出次数 | 占比 |
|---|---|---|---|
| 有自己的 Apple 页面（直达曲目页） | 209 | 633 | 37.2% |
| 没有，改指作曲家页（新） | 567 | 790 | 46.4% |
| 作曲家也不在表里（没有按钮） | 255 | 280 | 16.4% |
| 合计有按钮 | 776 / 1031 | 1423 / 1703 | **83.6%** |

这 83.6% 里只有 37.2% 是直达曲目页的；其余 46.4% 是作曲家页。

## 测试

`tests/js/browse.test.mjs`：`classicalWorkLink`（曲目页优先、只有作曲家时是作曲家页并带 kind、都不认识是 null、曲目 id 打架时走作曲家页、作曲家 id 打架是 null、表缺失 / 形状不对 / 非数字 id / `constructor` `__proto__` 都是 null、地址主机固定且没有 `search` 和 `?`）；用真实的解析器（有 key 的作曲家和只按名字认的作曲家）走一遍“曲目页 → 作曲家页”。手机宽度截图：作曲家页按钮、有自己页面的曲目页（不变）、作曲家也没有页面的曲目页（仍无按钮）。
