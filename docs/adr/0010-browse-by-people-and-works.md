# ADR-0010 — 按指挥、演奏家、作曲家、曲目浏览

日期：2026-11-16。状态：采纳并实现。**后续**：ADR-0014 补上了“已知缺口”里“同一首曲子写法不同不合并”的一部分：引号 / 括号 / 标记 / “op.” 与“作品”的写法折叠成一种（`workFold`、`nameFold`，只改写法，不看相似度），其余仍按写法分。ADR-0019（2026-11-19）又补上了下面“已知缺口”里的大部分：作曲家别名表、编曲者备注、作品号有无、译名行。起因：用户问“能不能像 Apple Classical 那样，按指挥、演奏家、作曲家、曲目来筛选，并且在演出详情里点名字就跳到对应页面”。

## 决定

| 问题 | 决定 |
|---|---|
| 页面形态 | `#browse/<种类>` 是索引（种类：`conductor` 指挥、`performer` 演奏家、`composer` 作曲家、`work` 曲目），`#browse/<种类>/<id>` 是其中一项的页面。发现页顶部有 4 格入口（带数量）；详情页「出演」里的指挥和独奏、「曲目」里的作曲家和每一首都能点。不增加底部标签，浏览页归在“发现”下（和 `#list/*`、`#concert/*` 一样）。索引页的 4 个标签用 `history.replaceState` 切换，和乐团标签一样，“返回”一步离开浏览页 |
| 怎么分组 | **只按写法分，不按相似度合并**（03_CONTRACTS 3.2：同名不同人不得自动合并，两种写法就是两项）。写法折叠 `bfold`：全角半角、大小写、重音、空白、点、中点、等号、连字符，加上两处：把代替长音“ー”的横线（U+2015/U+2014）当成“ー”，并去掉竖线（竖线是曲目 id 的分隔符）。其余一律不动：`北村陽` 和 `北村陽子` 是两个人，`J.シュトラウスII世` 和 `J.シュトラウス2世` 是两种写法 |
| 有 key 和没有 key | 作曲家和曲目有已审核的 key（别名表）时用 key。没有 key 的行，只在“折叠后的写法唯一对应一个 key”时并入那个 key；同一个折叠写法对应两个不同的 key（或同一作曲家+曲名对应两个不同的 work key）时**不并入任何一边**，保持各自的写法。结果不受数据顺序影响 |
| 曲目的身份 | 有 `work_key` 用它；没有就用“作曲家 id + 折叠后的曲名”（id 以 `~` 开头）。同一首曲子写法不同又没有 key，不会合并（已知缺口，见下） |
| 角色对应哪一页 | 指挥 → 指挥页；`recital_headliner`、`concerto_soloist` → 演奏家页；`other`（乐团、合唱团、个别记成“其他”的人）**不加链接、不计数**，乐团继续走 `#list/orchestra/<id>` |
| 怎么匹配 | 在浏览器里按折叠后的身份**完全相等**匹配，不用搜索页筛选那套“子串包含”（否则 `北村陽` 的页面会混进 `北村陽子`）。搜索页和 `/discover?composer=…` 等筛选不变 |
| 数据从哪来 | 列表那一次 `loadAll`（发现页本来就要等它画书架，不多一次请求）。`/discover` 的每个节目新增增量字段 `pieces`（全部曲目行：作曲家、作曲家 key、曲名、作品 key）；指挥、独奏沿用已有的 `conductors`、`soloists`。Python（`discover._summaries`、`api.DiscoverItem`）、`demo.js`、`docs/openapi.json`、03_CONTRACTS 同步，`check_demo_parity` 现在也比对这三个字段 |
| 范围 | 窗口就是发现页的 12/24 个月，页面上有同样的切换；不分地区（和搜索一致，含首都圈外）；已合并的重复卡片只显示主卡（ADR-0006，来自 `/discover` 本身）。已结束的演出不显示 |
| 脏数据 | 作曲家栏里混进备注或标题的（以括号、◎、※ 开头，含“/”，超过 20 个字，或就是“作曲”“振付”“編曲”“作詞”“指揮”）不进索引、不加链接 |
| 排序 | 节目数从多到少，同数按日文排序；同一名字的几种写法，页面标题用写得最多的那种 |

## 已知缺口（不在页面里猜，要改就改数据）

- ~~约翰·施特劳斯二世有「II世」「2世」等写法，索引里会拆成几项~~：ADR-0019 在页面的人工审核别名表里补了（`works.py` 没动，因为改它会改变已有行的 id、丢掉苹果链接表里的条目）。
- 同一首曲子没有 `work_key` 时：ADR-0019 已处理“作品号 / 目录号 / 调号有无”“长音符号”“前面加了歌剧 / 交响诗 / 芭蕾之类的类别词”“紧跟日文行的英文译名（要有作品号或曲号对得上）”；词序不同（フィンガルの洞窟序曲 / 序曲「フィンガルの洞窟」）、改编版、标题太泛的（ソナタ、ロンド、夜想曲…）仍然分开。
- 索引的搜索框只认日文写法和作曲家 key（如 `brahms`），不认中文译名。
- `other` 角色的人不在演奏家页里（例如某场把独奏者记成了“其他”，那一场不会出现在他的页面上）。
- ~~作曲家栏里“编曲者备注”会单独成项~~：ADR-0019 去掉了（括号里有「編」「編曲」「アレンジ」「版」等字样的结尾括号；被截断的括号只在剩下的是已知名字时才去）。

## 验证

- `tests/js/browse.test.mjs`：固定用例（写法折叠、有 key/无 key 并入、同一写法两个 key 不并入、竖线不破坏 id、精确匹配、索引计数）；另在真实数据上检查：详情页的每个链接落到的页面一定列出这场演出，索引里每一项的数字等于它的页面列出的场数。`tests/js/route.test.mjs` 增加 `#browse` 路由用例。两者都通过 `tests/test_ui.py` 进入 CI。
- `tests/test_filters.py`：`pieces` 字段内容，以及 HTTP 响应没有丢掉它（`DiscoverItem` 是带类型的响应模型，没声明的字段会被悄悄丢掉）。
- `scripts/check_demo_parity.py`：`demo.js` 与 Python 返回的 `pieces`、`conductors`、`soloists` 一致。
