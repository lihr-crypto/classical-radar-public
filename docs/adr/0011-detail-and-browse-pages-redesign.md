# ADR-0011 — 详情页和浏览落地页改版，去掉地区开关和搜索页的多余控件

日期：2026-11-17。状态：采纳并实现。**后续**：音源按钮已在 ADR-0012 改成 Apple Music Classical 的搜索链接（`musicHref` 改名 `classicalHref`），下文的 Apple Music 以 ADR-0012 为准。起因：用户给了另一个应用的四张截图，要求：详情页排版像其中的“演出详情”；点进曲目、作曲家等的页面像其中的“曲目页”，并能跳到 Apple Music 对应音源；发现页顶部的“首都圈 / 全国”没用；搜索页的搜索框和筛选按钮太多。

## 决定

| 问题 | 决定 |
|---|---|
| 详情页（`#concert/<id>`） | 去掉整块色封面。顶栏：圆形返回、圆形分享（支持系统分享的用系统分享，否则复制地址并提示）。然后：类别小标签、标题、日期一行、乐团行（七个乐团点进 `#list/orchestra/<id>`，其他主办方只写名字，因为没有“某个主办方的全部演出”这一页）。分块：曲目、出演、日程，块标题前有一小条赭金竖线（赭金只做形状，不做字色）。日程是一张圆角卡，卡里保留原来的每场“想去 / 已购票 / 已观演 / 其他状态”（“其他状态”菜单 2026-11-19 去掉了，见 ADR-0019）。卡下面两个大按钮：加入 Pickup、官网。“近期有重要变更”和“这场和某某卡片是同一场”两条提示放在标题区下面、曲目上面。售票时间线、提醒、事实块照旧在下面。所有原有功能都在，只改排版 |
| 曲目行 | 每首一行“作曲家 / 曲名”，整行进曲目页（`#browse/work/…`）；没有曲目页时退到作曲家页，再不行就是纯文字。作曲家页从曲目页里的“作曲”行进入。原先“作曲家一行、曲名一行”各有一个链接，现在合成一个 |
| 曲目页和人物页（`#browse/<种类>/<id>`） | 同一套顶栏，小标题“全部曲目”等，标题，曲目页有“作曲”行（进作曲家页），“找音源”块，然后“演出”标题（带数量和 12/24 个月切换）下面是演出卡片：日期时间、标题（两行截断）、乐团、指挥 / 演奏 / 曲目、场馆（多个场馆写“另 N 个场馆”）。每张卡一个链接，保留 `data-cid`，所以“返回”仍回到同一张卡 |
| 音源 | “Apple Music”按钮是一个**搜索**链接：`https://music.apple.com/jp/search?term=<作曲家 曲名>`（曲目页）或 `<名字>`（作曲家、指挥、演奏家页），搜索词用日文原写法，按码点截到 120 字，`encodeURIComponent`。在新标签打开，`rel="noopener noreferrer"`。不声称是某张专辑：数据里没有任何录音目录或专辑 id，页面的 CSP 是 `default-src 'self'`，也不能在浏览器里调 iTunes 搜索接口。纯函数 `musicHref` 在 `<browse-rules>` 块里，`tests/js/browse.test.mjs` 测它 |
| 发现页 | 删掉“首都圈 / 全国”和孤零零的“搜索与筛选”（它和底部“搜索”标签重复）。范围固定为原来的默认值首都圈：`state.region` 和 `inRegion` 去掉，换成 `inKanto`。首都圈外只有 33 / 537 场。发现页底部加一句“这里只列首都圈的节目；其他地区的请用搜索。”，免得它们悄悄消失。列表页（`#list/*`）同样 |
| 搜索页 | 留下：一个搜索框、一行类别（全部 / 主办方公演 / 钢琴独奏会 / 东京乐团 / 海外乐团）、数量、结果。去掉：提示段落、第二个“搜索乐团”框、“更多乐团”、“筛选”按钮和结构化筛选面板（作曲家 / 作品 / 指挥 / 演奏者 / 场馆，连带不再请求 `/discover/facets`）。七个乐团的多选小标签只在“东京乐团”开着时显示一行，离开这个类别就清空，避免看不见的筛选继续藏住结果。搜索框现在也匹配乐团的中文 / 英文名（数据里本来就有 `names`），所以输入柏林、Berlin 仍能找到柏林的乐团。`orchPicker` 不动，日历页继续用。全局加了 `[hidden] { display: none !important; }`：`.chip-row`、`.btn` 都是 flex，不加这条规则，`hidden` 属性压不住它们（上线前复核时发现乐团行在没选类别时也露着；顺带修了浏览索引页“显示更多”在没有更多时仍显示的老问题） |

## 没做的（原因）

- **作曲年份、乐章**：参考图的曲目页有，但仓库里没有这两项数据（`works.py` 只有作曲家 key 和曲目 key，乐章只留在原文里）。不编。要做就先建一张人工核对的曲目表。
- **“关注”按钮**：需要通知系统（ADR-0002：提醒目前只记录不发送）。不做假按钮。
- **Spotify / YouTube**：只做了要求的 Apple Music；同样是搜索链接，要加是同一个函数换个地址。
- **专辑直达**：见上，没有 id，不可能。

## 取舍与影响

- 搜索页删掉的结构化筛选是用户没有逐字点名的功能；理由是“按指挥 / 演奏家 / 作曲家 / 曲目浏览”（ADR-0010）已经覆盖前四项，场馆本来就能用搜索框找到。服务端 `/discover/facets` 和 `/discover` 的筛选参数没动，只是界面不再用。要找回，是在搜索页重新放一个入口，不用改后端。
- 详情页不再有整块色封面，封面规则（`<cover-rules>`）仍用于列表缩略图和书架，不受影响。
- 桌面宽屏下详情页不再是“左封面右内容”的两栏，改成单栏居中（最宽 760px）。
- 抓取的节目单里偶尔混进非曲目的行（例如读売日本交響楽団某场，主办方的售票通知被记成了一行“曲目”），旧版和新版都会显示它；这是数据解析的问题，不在页面里藏。

## 验证

- `tests/js/browse.test.mjs`：`musicHref`（作曲家 + 曲名、只有名字、空值无链接、特殊字符不能增加参数或路径、超长按码点截断不抛错、固定 https 主机）。
- `tests/test_ui.py` 里“前端不出现任何外部网址”的检查改成只放行 `https://music.apple.com/jp/search?term=` 这一条（在 app.js 里必须恰好出现一次；html 和 css 仍然不许有任何外部地址）。这是读者被带去的地方，不是页面加载的资源。
- `tests/test_ui.py`：搜索页只有一个搜索框、旧控件不再出现、乐团行只在“东京乐团”时显示并在离开时清空；发现页没有地区开关；CSS 里没有 `.hero`；Apple Music 链接带 `noopener noreferrer` 且地址固定。
- 手机宽度（390px）无头 Chromium 截图：详情页（亮 / 暗）、曲目页、作曲家页、指挥页、发现页、搜索页（含“东京乐团”）。
