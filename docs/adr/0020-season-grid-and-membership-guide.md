# ADR-0020 — 乐季总览：把各乐团新乐季的节目排成海报那样的表，按人和曲目挑场次，并带上会员 / 先行购票入口

日期：2026-11-20。状态：采纳并实现（待用户看过预览后上线）。起因：用户想把几个乐团新乐季（2027-28）的节目放在一个地方看，版式像 N響 的乐季海报（行是月份，列是 A/B/C 节目，格子里是日期、曲目、指挥、独奏），再按感兴趣的曲目、指挥、演奏家挑场次；还想知道要不要买季票 / 年票，要求把各乐团会员和先行购票的入口一起放进来。

## 决定

| 问题 | 决定 |
|---|---|
| 放在哪 | 新标签“乐季”（`#season`，`#season/<乐团 id | all>/<乐季起始年>`）。选中的乐团和乐季写在地址里，和 `#list/orchestra/<id>` 一样，刷新、复制链接、新标签页都是同一页 |
| 数据从哪来 | **只用现有数据**（`/discover` 的卡片）。2027-28 的节目 N響、都響、東響、日本フィル、新日本フィル 已经在库里；読響（官方演出列表还没发，只有节目单 PDF）和东京フィル（还没公布）没有，页面如实写“已收录的官方演出列表里还没有 2027-28 乐季的节目”，不编、不补。不新增采集，不动 `works.py`、本地 id、接口、每日任务 |
| 乐季怎么算 | N響 每年 9 月开始，其他乐团 4 月开始（`SEASON_START`）；一张卡按它**第一场有日期的演出**归到某个乐季某个月。“本季”只含今天以后（`/discover` 只给今天起的），按钮上写“（今天起）” |
| 列怎么分 | 按标题里的系列写法（`SERIES` 表，正则，第一条命中的赢）：N響 A/B/C；都響 A/B/C/プロムナード；東響 定期/川崎定期/オペラシティ/名曲全集；日本フィル 東京定期/横浜定期/さいたま定期；新日本フィル トリフォニー/サントリー/すみだクラシックへの扉；読響 定期/名曲/土曜·日曜·横浜マチネー/アンサンブル/大阪。认不出的进“其他公演”，**一张卡也不会丢**（测试保证每张卡恰好在一个块里）。新日本フィルの〈オペラシティ・シリーズ〉两场按官方说明并进サントリー列 |
| 块怎么合 | 同一个月、同一列、**曲目、指挥、独奏都一样**的卡并成一块，日期写在一起（日本フィル 东京定期 金/土、すみだクラシックへの扉 金/土 就是这样）；没有曲目的卡永远不合 |
| 日期精度 | 只有“月”的演出写成“6月（日期未定）”，不给它编一天；完全没日期的单列在格子下面 |
| 表头的会场和时间 | 从这一列自己的演出里算（最常用的两个会场、不同的“星期+开演时间”最多三个），不写死 |
| 按人和曲目挑 | 一个搜索框 + 四类（指挥、演奏家、作曲家、曲目，复用 `<browse-rules>` 的 id 和名字）；选中的是 chip，**命中任意一个**的块被标出（左边赭色框，命中的名字和曲目行加赭色下划线）；“只看命中”开关；每列表头写“命中 a/b”，所以能看出自己的兴趣集中在哪个系列（买哪个系列的会员券才划算一目了然）。选择存在本机 localStorage（`cr_season_pick`），id 对不上时按写法找回，找不到就保留 chip 让人自己删 |
| Pickup | 每个块有书签按钮，直接用现有的 `PUT/DELETE /me/pickups/<id>`；合并块里的几张卡一起加 / 一起去掉 |
| 会员 / 先行购票 | 新文件 `web/memberships.js`（`window.CR_MEMBERS`），和 `classical-links.js` 同一种做法：手写、人工核对、随站点打包，不走接口，不改 CSP。每个乐团：会员种类（`series` 连续券 / `presale` 不买连续券也能先行的办法）、官方链接、电话、**带日期的发售事件（每条写明出自哪一页）**。页面上有跨乐团的“购票日程”（还有 N 天 / 今天 / 已开始）和每个乐团下面的“会员 · 购票入口” |
| 官方还没公布的 | `announced: false` 的乐团（N響、东京フィル）**没有任何发售日期**（测试保证）；去年的节奏单独放 `lastYear`，标题写“去年的节奏（只供参考，不是今年的日期）”，也要写明出处。N響 的节目海报写明“料金、発売日等チケットの詳細は2027年4月上旬に発表予定” |
| 不做什么 | 不判断“该不该买”，只给事实、官方价格（官网写的）和各系列的命中数；不从价格或去年推算今年的日期；东响官网有一次维护中，那时只用了项目自己从官网公演页采到的售票时间 |

## 已知缺口（不做，记在这里）

- 読響、东京フィル 的 2027-28 节目：读响只有官方 PDF，东京フィル 还没公布。等官方演出列表出来，每日任务会自己采进来，这个页面不用改；PDF 要采的话是一个单独的解析器，像 ADR-0009 那样。（2026-11-20 更新：读响的 PDF 没有文字层，解析器做不了，改成人工转录的数据文件，见 ADR-0021。）
- 发售日变了：`memberships.js` 是手写的，日期改了要人来改（`checked` 日期会在页面上显示，让人知道是哪天读的）。没有自动比对，因为比对失败会卡住每日数据 PR。
- 这里只列首都圈的节目（和发现页一样），东响新潟定期、都響大阪公演等不在表里；搜索和乐团的“全部公演”里有。
- 手机上表头隐藏，每个块自己带“系列 · 会场”小标；桌面上是真正的多列表，超过 5 列时靠页面自己的宽度（最大 1500px）。

## 2026-11-20 修订：少放说明文字，修搜索

- 手机上看到页面说明文字太多：去掉了“按人和曲目挑场次”的标题和说明段、底部“这里只列首都圈…”（页脚已有“未收录不代表没有公演”）、发售日程的说明段（只留“官网 MM/DD 确认”）。搜索框的占位文字自己说明用途。
- 乐团有节目时，会员 / 购票入口一律折叠起来（原先选中单个乐团时自动展开，一屏都是字）；发售日程因此不再在选中单个乐团时省略，永远列在表上方（跨乐团的这张表不再带每条的长说明，长说明留在各乐团自己的入口里）。只有“还没有节目”的乐团才自动展开它的入口。
- 搜索建议整页变成 `[object HTMLDivElement]`：`replaceChildren` 要的是一个个节点，不是数组；有结果的分支传了数组。改成展开传入。

## 2026-11-20 修订（二）：长列表进弹窗，只看一个乐团的最新一季

起因：用户在手机上看到“全部名单”和“购票日程”一展开页面就很长，且不需要 2026-27 乐季。**下面几条取代正文表里对应的说法**（正文里“选中的乐团和乐季写在地址里”“跨乐团的购票日程”“全部乐团”等已不再成立）。

| 问题 | 决定 |
|---|---|
| 乐季 | 页面只显示**有节目的最新一季**（现在是 2027-28）；不再有乐季切换，也不再有“（今天起）”的 2026-27。标题旁一个不可点的小标签写季名。某个乐团这一季没有节目就写“暂无 … 乐季的节目”，**不会退回显示旧的一季**。旧链接里的年份被忽略（`seasonRoute` 不动，所以 `#season/all/2026` 之类仍能打开） |
| 乐团 | 去掉“全部”标签，也不能再点已选中的乐团取消。一次只看一个乐团：地址里的 id，否则上次选的（localStorage `cr_season_orch`），否则排在最前的 N響（`pickOrch`，`<season-rules>` 内，有测试）。因此购票日程自然只显示这一个乐团 |
| 已选的人和曲目 | 属于使用者，不属于乐团：换乐团后还在，只是在新乐团里命中为 0，状态行写“这个乐团没有命中的节目” |
| 弹窗 | 新的通用 `makeSheet`：原生 `<dialog>` + `showModal()`，手机上从底部升起（最高 85dvh），桌面居中。Esc、右上角 ×、点灰色区域、底部按钮都能关；打开时背后的页面不滚动（`html:has(dialog.sheet[open])`，弹窗被页面换掉时锁跟着消失）；焦点落在 ×，不会弹出手机键盘。弹窗放在所属页面里，离开页面就没了 |
| 全部名单 | 搜索框右边一个“全部名单”按钮，没有任何名字时禁用。弹窗里四个标签（指挥 / 演奏家 / 作曲家 / **曲目**，曲目是新加的，67 条左右，可在弹窗里的输入框里筛）；点一个名字就是挑选（和页面上搜索框的选择是同一份 `S.picks`）；底部“清空”“完成 · 已选 N”。弹窗开着时只改弹窗和 `S.picks`，**关闭时才重画一次页面**（存 localStorage），所以弹窗不会在手指下被重建 |
| 购票日程 | 页面上只剩一行：“购票日程 / 最近 11月25日 还有 5 天 · 共 6 条未开始”，或“没有还没开始的发售日 · 已开始 1 条”；点开是弹窗，里面“还没开始 N 条”“已开始 N 条”**全部列出、没有折叠**（原先都響只露出“已开始 1 条”的折叠，其他乐团却展开，现在一致）。没有任何发售日的乐团（N響、东京フィル）不显示这一行 |
| 会员 · 购票入口 | 仍是折叠的 `<details>`（没有节目的乐团自动展开），**不再重复列发售日程**（都在弹窗里）；弹窗里的每条带那句“给谁”的说明 |

### 修订（三）：乐季页的“全部公演”只打开这一季

用户指出：乐季页里点“全部公演”，看到的不只是这个乐季的这个乐团，会引起误会。查实：这个链接原先是 `#list/orchestra/<id>`，即“该乐团未来 `state.months`（默认 12）个月内每个乐季的公演”，所以 N響 2027-28 的页面写“27 个节目”，点进去却是 41 条（含 2026-27 的，缺 2027-28 后半段）。

- 链接改成 `#list/orchestra/<id>/<乐季起始年>`。`listRoute(arg, sub, season)` 多收第三段，格式不对（不是 20xx）就当没有；只有乐团列表接受乐季，prototype 名字仍然不是路由。
- `viewList` 带乐季时：读和乐季页一样的 24 个月，取该乐团的卡片，用 `seasonGrid(...).items`，**正是乐季页那张表里的卡片**（逐个乐团核对过卡片编号完全一致）；标题“N響 2027-28 乐季”，不放乐团筛选标签，返回按钮写“乐季”并回到乐季页（直达链接也回乐季页，不回发现页）。
- 条数写“共 N 条”，不写“个节目”：乐季页把同一套节目的周五周六合并成一个“节目”（日本フィル 36 个节目 = 46 条），清单每张卡一行，两个数不是一回事。
- 不带乐季的 `#list/orchestra/<id>`（发现页的乐团货架、详情页的乐团行）不变。

没做：把“会员 · 购票入口”也改成弹窗（用户没提；它默认折叠，只有没节目的乐团才自动展开）。

验证：`tests/js/season.test.mjs` 新增 `pickOrch`、`saleSummary` 两条；弹窗的实际行为（打开 / 挑选 / Esc / 点灰色区域 / ×、关闭才重画、背后页面不变长、离开页面锁消失、旧链接、记住乐团）用无头 Chrome 的触摸模拟逐条检查过。iOS Safari 上背后页面是否完全不滚动，没有真机验证（只设了 `overflow:hidden` 和弹窗内 `overscroll-behavior: contain`）。
