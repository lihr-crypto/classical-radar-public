# ADR-0009 — N響下个乐季：读乐季速报 PDF，先于官网年度数据上线

日期：2026-11-14。状态：采纳并实现。起因：用户问“能不能自动采集 N响等乐团新乐季的演出信息”，并同意解析 PDF。

## 问题

N响每年 10 月前后在官网新闻里发〈速報〉下个乐季（2027-28 乐季是 2026-10-09）。完整的日程、指挥、独奏、曲目只在新闻附带的一页 PDF 海报里；官网的年度数据文件（`archive_concert_2027.json`）要几个月后（“詳細決定”前后）才会列出这些演出。其余几个乐团（都响、东响、日本爱乐）把新乐季直接放进了演出列表，已在采集范围内；新日本爱乐、读响还没公布。所以缺口只有 N响。

## 决定

| 问题 | 决定 |
|---|---|
| 怎么找到海报 | 读 `news/json/news_all.json`（robots 全放行，列表页自己也读它），取标题含“YYYY-YY シーズン定期公演 … プログラム発表／日程・指揮者決定／出演者・曲目発表”的最新一条，前提是那个乐季还没结束；再读那条新闻页里的 PDF 链接。每天 3 个请求（新闻索引、公告页、PDF），走原有 `Reader`：HTTPS、注册域名、同域 2 秒、401/403/429 即暂停 |
| 怎么读 PDF | `src/classical_radar/season_pdf.py`，依赖 `pypdf`（纯 Python、无下级依赖，已写入 `pyproject.toml` 和 `requirements.lock`）。海报是 A/B/C 三栏 × 月份行的网格：**按页面坐标把文字对到格子里，不按文字流的顺序**（文字流顺序不是网格顺序）。PDF 里有些行被拉开字距（“コ リ リ ャ ーノ”），按“行里有没有两个以上两字以内的纯日文小词”判断并合并 |
| 怎么防读错 | 海报自带校验：每个日期旁印着星期，必须等于真实星期；每个月份行必须有月份标签；每场必须有曲目；两栏不能映射到同一个节目。任何一条不符，整张海报被拒绝（`ParseError`），宁可少一个乐季，也不把错的日期当官方信息显示 |
| 身份和链接 | 海报里的节目在官网还没有自己的页面，所以身份地址和“官网”链接都用那条真实存在的公告页，加 `?program=202709A` 区分每一场（`canonical()` 保留查询串）。**不**用将来的官网地址当身份，否则几个月里“官网”按钮都指向 404 |
| 官网年度数据出现后 | 同一场原地迁移：同一行 `concert`，只把 `identity_key` 改成官网新页面。内部 id（演出和场次）不变，收藏、提醒挂在 id 上，下一次入库按原来的方式更新，不会出现第二张卡片。“官网是否已经列出这一场”只有一条规则（`_official_match`），去重和迁移共用：先按节目代号对官网地址的文件名（`/concert/202709A.html`，2026-27 的 21 个节目全部如此），不行再找**日期集合完全相同的定期公演**。官网已列出的节目，海报里的同一场不再入库。迁移不依赖海报这一步成功：海报读不了的那天也会迁 |
| 新版公告页 | 同一个乐季后来又发新公告（“出演者・曲目发表”）时，已存的节目把地址原地改到最新公告页（`season_rekeyed`），不会在新页面下再生一张卡片 |
| 迁不了怎么办 | 目标地址已经是另一张卡片时不合并，记一条警告（每日运行变红），请人看是不是重复；不留下静默的孤儿 |
| 失败怎么处理 | 海报这一步捕获所有异常，失败只记一条 `warnings`，年度数据照常入库；`refresh_report.py --strict` 看到 `warnings` 会让每日运行变红 |
| 确认方式 | 与所有来源一样入库为待确认；每日自动确认的规则不变（字段齐全：具体日期、会场、都道府县；NHKホール、サントリーホール都在已知会场里） |

## 验证

用去年同期的海报（2026-27，2025-10-06 发布）对照官网年度数据文件今天的内容（`tests/test_season_pdf.py`，夹具在 `tests/fixtures/nhkso-season-2627.*`）：

| 项目 | 结果 |
|---|---|
| 节目是否都能在官网数据里按地址找到 | 21 / 21 |
| 日期和开演时间一致 | 21 / 21 |
| 会场一致 | 21 / 21 |
| 指挥一致 | 20 / 21（另一场是官方后来临时换人：布隆斯泰特换成巴梅特） |
| 曲目 | 作品名本身一致；官网后来多加了“N响100年特别企画”这类副标题和版本说明，所以整表不逐字相等 |

2027-28 乐季的海报解析出 27 个节目（A/B/C 各 9 个，每个 2 场，共 54 场）。12 月 A 节目在 11 月开（11/27–28）、5 月 C 节目在 6 月开（6/2–3），都按海报底部的注释处理，节目代号仍用印着的月份。

## 已知限制

- 官网年度数据里的这一场既不叫 `<节目代号>.html`、日期也和海报不完全相同（改期了），迁移对不上，会出现两张卡片；极少见，出现时走“疑似重复”的人工复核。
- 新公告页改了某个节目的日期、官网年度数据又用不同的文件名、按新日期列出它：去重按海报上的日期算，迁移按库里存的日期算，这一场只会搬到新公告页，官网页面进来后会多一张卡片，且没有警告。极少见，出现时走“疑似重复”的人工复核。
- 新公告页去掉或改了某个节目的代号：旧公告页下的那一行留在原地，不会被标成消失（`complete=True` 只判断出现在本次抓取里的整场演出）。
- 开演时间只取自每栏表头（“土 6:00pm／日 2:00pm”）。如果哪个月的开演时间不同、只写在脚注里，会错；脚注文字不解析。
- `Reader.get_bytes` 先收完整个响应再检查 5 MB 上限（受 25 秒超时限制，域名限定在 nhkso.or.jp）。
- 海报是“速報”，曲目和出演者可能变；官网年度数据出现后以它为准，曲目和出演者会作为一次实质变更记录下来。
- 只读 A/B/C 定期公演的网格。特别公演页（去年海报的第 2 页）不解析；海报版式如果大改，会被校验拒绝并让每日运行变红，需要改解析器。
- 其他乐团的新乐季靠原有的列表采集，不在本决定内。`NHK_TICKET_NEWS`（开售日公告）仍是每季手改的一个地址。
