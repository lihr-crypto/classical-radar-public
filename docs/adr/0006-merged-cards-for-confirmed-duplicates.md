# ADR-0006 — 已确认的重复卡：人工选主卡，列表只显示主卡（不合并数据）

日期：2026-11-11。状态：采纳（方案经评审两轮：第一轮打回 4 处，改后通过，另有 2 条必须项已并入）。接着 [ADR-0003](0003-cross-source-duplicate-review.md) 留下的问题：“已经都确认的两张卡，发现页仍然会出两张”。

## 要解决的问题

线上数据（2026-11-11 的 `site-data/concerts.json`，456 个节目）里有 9 对“不同来源、同一天、场馆兼容”的已确认节目：东京交响乐团 × 神奈川艺术协会 4 对，Japan Arts × 神奈川艺术协会 5 对。发现页和日历各出两张。ADR-0003 只能把 `needs_review` 的一条藏起来，对已确认的两张无能为力。

## 决定

| 问题 | 决定 |
|---|---|
| 谁决定是不是同一场 | 仍然只有人。程序只提示，不自动合并（ADR-0001）。待确认页新增一块“已确认、可能是同一场”。 |
| 哪张是主卡 | 你的决定（2026-11-11）：乐团/主办方官网优先。落成 `Source.card_rank`：七家乐团 0，Japan Arts / KAJIMOTO 1，神奈川艺术协会 2；数字小的被**建议**为主卡，同级不建议。存下来的仍是人点的那一个（`duplicate_review.concert_id` = 被收起的，`other_concert_id` = 主卡）。 |
| 能不能丢场次 | 不能。被收起的卡每一场未来演出都必须在主卡上有同一天、场馆兼容的一场，否则拒绝（422）；这时只能反过来选，或不合并。主卡也必须已确认。 |
| 列表怎么显示 | **按场次**处理，不按卡：被收起卡的某一场，只有当主卡在**同一批结果里**有同一天、场馆兼容的一场时才不显示。筛选或日历范围把主卡那一场滤掉时，被收起卡的那一场照常显示。主卡带 `other_sources`。 |
| 详情页 | 两张卡的详情页都在。主卡多一行“其他来源”，被收起的卡提示“和某某的卡片是同一场”。 |
| 收藏、状态、提醒、售票阶段 | 不搬、不合并，各留在自己的卡上。两个来源各卖各的票，开售时刻本来就可能不同。 |
| 决定存在哪 | 数据库（`duplicate_review`）之外，再存成 `site-data/same_concert.json`，键是 `来源\|URL`（数据库重建后 id 会变，身份键不变）。“是同一场”和“不是同一场”都存。 |
| 线上站点 | `scripts/build_site.py` 每次构建都用这个文件重新套一遍（同样的守卫），写进 `site/data/concerts.json`：被收起的节目带 `duplicate_of`，它的每一场带 `same_as`（主卡上顶替它的场次 id）。`site-data/concerts.json` 本身不带这些标记。页面端没有场馆比较逻辑。 |
| 决定失效 | 和 ADR-0003 一样：两张卡不再同日同场馆（改期、取消、已过）时，决定不再生效，两张卡各自显示；文件里的条目会被跳过并打印，不会强行套用。 |

## 文件与命令

- `classical-radar duplicates-dump DB`：把数据库里的决定写进文件。**只合并不缩减**：同一对以数据库为准；同一张被收起的卡换了主卡时，旧条目被替换；其余条目原样保留。
- `classical-radar duplicates-apply DB`：把文件重放进数据库（走 `decide()`，守卫全部生效，按决定时间先后）。认不出的节目、过不了守卫的条目会列出来，不强行写入。
- **撤销要注意**：在待确认页撤销只改数据库。文件里的条目要用 `duplicates-dump --prune` 才会删掉；不加 `--prune` 时 dump 会在结果里列出“文件里有、数据库里没有决定”的条目，提醒你下次重放会把它带回来。`--prune` 只删两张卡都在这个数据库里、且数据库里没有决定的条目；数据库里没有的节目对应的条目一律保留。

## 没做 / 已知限制

- **不是数据合并**：两条 `concert` 都在，筛选计数（facets）、来源覆盖统计仍各算一条。
- **日历上的开售事件不去重**：被收起卡的开售时刻仍然显示，同一场可能出现两个来源各自的开售。
- **线上站点的合并只在构建时计算**：判断“是否仍然同日同场馆”用的是构建当天；两次构建之间数据不变，所以不会错，只是决定失效要等下次构建才反映。
- **线上站点没有待确认页的写入口**：决定要在本地做，或直接改文件后走 PR。
- 被收起的卡如果有主卡筛选条件匹配不到的属性（例如只有它标了某位作曲家），按那个条件筛选时它自己照常出现，不会消失。
- 主卡排序只是三档，同档（两家乐团、Japan Arts 与 KAJIMOTO）不给建议。
