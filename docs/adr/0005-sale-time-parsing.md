# ADR-0005 — Japan Arts、东京交响乐团、神奈川艺术协会的开售时刻解析

日期：2026-11-09。状态：采纳（用户选择“补解析开售时刻”；动手前经评审，评审意见已并入下表）。动机与数字见 [开售时刻覆盖报告](../reports/P0_3_SALE_TIME_COVERAGE.md)：Japan Arts 42/42 页、神奈川 8/8 页、东响 4/8 页写了开售时刻，补之前解析器读出 0、2、0 页。

**本 ADR 修改 [ADR-0001](0001-p1-first-slice-decisions.md)**：ADR-0001 要求开售时刻“年、日、时刻都明确写出”才解析。现在允许**页面没写年份时由括号里的星期定年份**（规则见下），并且每条记录会带 `year_basis`（`explicit` / `weekday`）。日期没有时刻的行仍然不解析。

## 决定

| 议题 | 决定 | 理由 / 后果 |
|---|---|---|
| 年份 | 写了就用（`explicit`）。没写：必须有括号里的星期，在“第一场演出所在年、前一年”里找日期**不晚于第一场演出**且星期相符的那一个，**恰好一个**才用（`weekday`）；没有星期、没有第一场演出日期、星期对不上、或都对得上，一律不出记录 | 同一个月日在相邻两年星期不同，所以星期相符时年份唯一；宁可漏，不猜。晚于演出的开售（如开演后才有的追加发售）因此不出记录，是失败安全的 |
| 时间 | `a.m. / p.m.` 先换成 24 小时再存（“2:00p.m.”是 14:00）。没有时刻不出记录 | `parse_date` 只认不带点的 `am/pm`；不归一化会把下午存成凌晨（评审指出） |
| Japan Arts 范围 | 只读“チケット発売情報”标题紧跟着的那个 `ol.list-type-7`（先去掉 WEB/TEL 标签）；页面其余部分是别的公演的导航卡片，不读 | 避免把别人的日期混进来（与 ERRATA E1 同类） |
| Japan Arts 行 | 标签里“※…”的备注和网址要切掉（真实数据里出现过）。每个 `li` 取**第一个**日期时刻作为开始；“～”后的窗口结束日期不算；“受付期间：…”以“受付期间”为标签；没有任何标签的行丢弃，**记录绝不带空标签** | 评审要求 |
| 带会场名的标签 | 标签里写了会场名（如“アクロス福岡 先行”）而该名字不在本场演出的会场里 → 不出记录；在则保留 | 评审指出：Japan Arts 的开售区块可能覆盖巡演各站 |
| 阶段类型 | 只有“一般”命名为 `general_sale`；东响的“東響会員先行発売”是 `member_presale`（页面写了会员）；**其余一律 `other`，标签原样作为说明**（学生、ジャパン･アーツぴあオンラインチケット、先行、オンライン先行、セット券…） | 页面没说是会员先行还是抽选，就不替它下结论；提醒只需要 `starts_at` |
| 神奈川 | 一行一条，另外读“【４公演セット】2026年10月23日…”“【１回券】…”“＜２公演セット券＞…”这种括号在前的写法（括号里不含“セット/回券”的不算开售；括号行后面还写着先行、会员、抽选、プリセール的，不算一般发售）。标签从最具体的开始匹配：`セット券一般発売` / `１回券一般発売` / `セット券` / `一回券` / `一般発売(日)`。套票 → “一般（セット券）”，单场票 → “一般（1回券）”（原有，说明文字沿用原来存的原文，所以已有数据库再同步**不会**多出重复阶段），其余 → “一般”。括号里的“電話受付は6月8日～”不是开始 | **改变了原有测试的预期**：原来只要“一回券”（测试注释写“not the series set”），那是旧解析只取第一处匹配的结果，不是套票开售时间不对；页面明确写了，且说明文字不同，入库键（演出、阶段类型、说明）不冲突 |
| 东响 | 東響会員先行発売 / オンライン先行発売 / 一般発売，分隔符 `… ： :`，前面的 □■◇ 无所谓；日期可以是“2025年11/27”“12/1”或“2026/2/6”；没有时刻的行不出记录。**页面按票种分组**（“■定期会員券”“■選べるプラン・1回券”，或旧版的行内“年間セット券 □…”）：每组三行，**组名写进阶段说明**（如“一般（定期会員券）”） | **真实同步暴露了第一版的缺口**：第一次真实同步时 69 场东响演出里只有 10 场有阶段，因为同一页的两组日期被当成“同名重复”拒绝了。组名只取日期行上方、含“券/プラン/セット”的短行（页面明写的票种）；上一行是票价、场馆名或备注时不取，沿用当前组名，宁可不分组也不猜 |
| 挂到场次 | 仍然只经 `link_presenter_claims`：**页面只有一场演出才挂**；新增一条：**同一页里有两条阶段类型和说明都相同的行，就全部不挂**，原因写明 | 评审指出：列表里一场、文字里却有两组日期的东响系列页，不能让一场演出悄悄挂上错的那一组。KAJIMOTO 现有证据（15 页 22 条）没有重复，不受影响 |
| 传参 | `parse_detail(source, html, url, reference=None)`，东响和神奈川用 `reference`；`sync._paged` 传该网址列表里最早的演出日；Japan Arts 用详情页第一场演出日。`reference=None` 时没写年份的行被跳过 | |
| 提醒 | 新阶段是普通的 `ticket_phase`（Japan Arts 渠道 `official_presenter`，东响和神奈川 `official`），提醒走原来的 `personal.put_reminder`：要求精确时刻、官方渠道、开售时刻未过。测试走这条真实路径 | 链接器里的 `reminder_eligible: False` 标志并不参与 `put_reminder`，所以不是旁路 |

## 已知限制

- **入库层只增不减**：页面上某个标签被改写（例如“一般” → “一般発売”），旧阶段会留在库里，新阶段另算（键里含说明文字）。需要“页面上没有了就撤销”的话要另做。
- **过去的开售也会入库**（`current_status` 为 `unknown`），界面显示“已开始”。
- **多场演出页仍然不挂**：Japan Arts 有 11/42 页，其中未来开售 12 页里的 4 页。开售区块是否适用于每一场没有逐页确认，放开需要你单独决定。**2026-11-11 你的决定：继续不挂。**
- **带会场名的标签只在含“ホール/劇場/会館/アクロス/センター/シンフォニー/Hall”这类词时才会核对会场**：写着别的会场但不含这些词的标签（如“オペラシティ 先行”）会保留；这只影响单场演出的页面，风险有限。
- **没做**：窗口结束时间（`ends_at`）、把“先行/学生”映射成会员先行或抽选、只有日期的行、读卖和日本爱乐（页面没有数据）、界面。
- 测量用的 `salecoverage.py` 是与入库解析器**独立**的另一套实现（用来互相核对，不要合并）。

## 真实同步验证（2026-11-09）

手动跑了一次真实同步（日本艺术公司、神奈川艺术协会、东京交响乐团，186 个请求，没有页面失败，写入临时数据库），再用同一批缓存的详情页重放修好后的解析（详情页读缓存，列表页重新取，另发 36 个请求）。数字、单位和合理性检查见 [开售时刻覆盖报告](../reports/P0_3_SALE_TIME_COVERAGE.md) 的“真实同步的结果”与 `evidence/p03/sale-sync-2026-11-09.json`（单位是演出：东响 10 → 37 / 69 场有阶段，神奈川 57 → 62 / 63，Japan Arts 29 / 55，不变）；重复阶段、开售晚于演出日、开售早于 2024 年三项检查都是 0。**阶段数不等于提醒的时刻数**：东响 139 个未来阶段去重后只有 12 个不同的（开始时间、说明）。临时数据库不是你的正式数据库，也没有保存。

## 追加的已知限制

- **东响的组名会随页面改动**：说明里带着组名（如“一般（定期会員券）”）。以后页面上这一行被改了字，同步会新增一批阶段，旧的和挂在旧阶段上的提醒仍然留着（入库只增不减）。你正式的数据库里原来没有东响的开售阶段（旧解析读出 0 条），所以今天没有这种遗留。
- 组名只在含“券/プラン/セット”时才取；页面用别的词写票种（例如“前期会員”）时不会分组，同名的两组日期会因“同名重复”不挂，这是失败安全的。
