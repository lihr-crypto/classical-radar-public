## 已确定的产品规则

- 三层模型为 **Concert 节目 → Performance 实际场次 → TicketPhase 售票阶段**。
- 「我的 Pickup」按节目关注，可选择具体场次；购票/观演状态按场次；提醒按售票节点。不要混成同一张收藏表的同一粒度。
- 官方公布日期、系统首次收录时间、实质更新时间分别记录。没有官方公布日期时只能称「最近收录」，不从 `sitemap lastmod` 或抓取时间推定。
- 保留按作品、作曲家、指挥、演奏者、乐团、场馆的轻量结构化筛选，不做全球曲库或未经审核的实体合并。
- 第三方未核实消息独立展示，不混进官方确认场次，不直接生成开票提醒。已官宣但日期未定的项目也须分区。
- 保留节目级 Pickup、双日期日历、售票时间线、个人购票管理与提醒；编辑精选暂缓。
- 正式系统用简单服务端过滤/分页、单用户优先；数据库、认证和部署方式需根据 P0 结果决定，不为 POC 搭建全套服务。
- 票务未知值保持 null；只有月/日的精度不制造分钟级时间。不得把会员先行当一般销售，不从「発売中」反推初始开售日期。
- UI 未来参考 Apple Music 的视觉及演奏会びより的功能结构。P0 不实现 Vue 页面，不提交第三方截图/海报作为产品素材。
