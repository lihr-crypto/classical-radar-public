# 05. 验收方法：正确性 × 覆盖率 × 时效性

## 数据质量不是“8 个样本达到 95%”

第三方 Review 指出原先小样本与95%阈值不匹配。修订如下：

### A. 解析正确性（小样本机制验证）

- 每个通过 POC 的来源选**至少8个具有差异性的合法样本**，覆盖列表/详情/售票公告、缺失日期、跨多场和分页；8个是 fixture 回归起点，不用于宣称95%置信度。
- 所有样本对官方原文手工标注核心字段（金时间、日级时间、场馆、乐团/独奏分类、售票/截止时刻）并记录错误条目。**任何已确认分钟级售票时间的错误关联或凭空生成都阻塞上线**；其余错误逐项汇总修复。
- 持续积累样本，统计 exact match / 召回率及 n/N，不以小样本包装为稳定的95%生产准确率。

### B. 来源内覆盖率（避免只采到10场却声称成功）

- 在确定的日期范围/页面列表上人工枚举官网公演总数 `N`；采集的有效场次数 `n`；显示 `n/N`，列出遗漏和原因（网页不可访问、特殊格式、条款限制等）。
- **明确分开** `官网未公布` 与 `官网已公布但采集失败`；避免将空售票时间错误计入提取失败。
- 跨来源“日本整体覆盖率”在没有独立完整基准时**不得估计为一个百分比**；只能列出各来源覆盖和已知盲区。

### C. 更新及时性（持续运行后评估）

- 模拟新增、开票更新、撤销、改期验证 diff/通知逻辑；记录 `detected_at - official_change_known_at`。真实的长期时效必须依赖持续监测，初次 POC 不宣称达到某固定小时 SLA。

## 发布阻塞测试

| ID | 场景 | 验收 |
|---|---|---|
| T01 | 七团白名单 | 仅七个 source_id；用户排除的四团无 adapter 或自动扩展任务 |
| T02 | 海外与独奏会验证 | 至少来自互补官方源的真实日本演出，类型正确；缺数据明显提示覆盖不足 |

| T18 | UI 与无图降级 | 手机与桌面可用；无照片也有可读的视觉卡片；演出/售票/全部日历工作 |

## Gate 判定

- **P0 Gate A/B**：需要至少一个完整真实源链路 + 海外乐团/钢琴独奏会的实际核实结果（未覆盖须标 No-Go/Conditional），附 n/N；不能把调研替代实测。
- **P1 Gate**：真实公演数据可贯通发现→详情→Pickup→场次状态→日历→主动开启提醒；零已知虚构的关键日期，明确来源证据与最后核验时间。
- **生产部署前**：站点政策可接受、提醒假发送/失败恢复验证、访问控制、备份方案、费用与用户许可检查。
