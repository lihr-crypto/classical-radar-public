# 01. Product Requirements — v1.5

## 要解决的两个问题

- **找得到**：不用事先知道乐团/钢琴家的名字，能从**未来日本实际公演**中发现海外名团与钢琴独奏会；也能持续关注七家本地重点乐团。
- **不漏票**：从官方网页/公告提取开票、先行抽选、一般销售、结果公布、支付期限和追加销售，整理为可追溯时间线和个人提醒。

## 用户旅程

`发现（全部/12个月/首都圈优先/最新公布） → 查看乐团/钢琴家与曲目 → Pickup 节目 → 选感兴趣场次 → 明确开启提醒 → 抽选/购票记录 → 日历/已观看`。

## 必须实现（MVP）

| ID | 需求 | 验收重点 |
|---|---|---|
| U1 | 七家国内重点乐团演出自动汇总 | 每源状态可见；官网实际已公布公演按覆盖口径对照 |
| U2 | 海外名团来日 + 国内外钢琴独奏会发现 | 至少两个互补的**经 POC 通过**的官方数据源；只展示有日本公演证据的对象 |
| U3 | 演出详情与完整曲目 | 指挥、演奏者角色、按顺序曲目、各场次、场馆、官方链接 |
| U4 | 组合过滤与双浏览模式 | 按公演浏览、按已有日本公演的乐团/钢琴家聚合；作品/作曲家/人/场馆筛选 |
| U5 | 售票时间线 | 多渠道/会员先行/抽选/一般/追加、开始/截止/结果/支付；日期精度显式表达 |
| U6 | 我的 Pickup | 节目级个人收藏与优先级；可进一步选择具体场次；**默认不启用提醒** |
| U7 | 购票状态 | 场次级的想申请、已申请、中签、已购票、放弃、已观看及个人备注 |
| U8 | 日历 | 演出/售票/全部；月视图和列表视图；清楚显示时区与未知时间 |
| U9 | 关键提醒 | 仅明确订阅且经核实、精度足够的时间节点；更改/取消后正确失效；防重复 |
| U10 | 可审计性 | 演出和关键日期显示官方 URL、最近成功核验、发布日期来源或首次收录标识 |
| U11 | 官方 URL 导入 | 粘贴 URL→候选抽取→校验/人工确认→入库，作为自动采集失败时兜底 |
| U12 | 来源健康与覆盖说明 | 无来源覆盖时不能宣称“近期没有演出”；单源失败不删除历史 |

## 页面

- **发现（Radar）**：待处理开票、首都圈新公布、其他地区、海外名团、钢琴独奏会、按公演/按乐团与钢琴家切换。首页卡片优先真实信息，未确认线索独立。支持地区/月份/类型/售票状态/组合筛选。
- **详情**：视觉封面（有权使用的图片或自绘排版）、介绍（可选）、曲目、人员角色、实际场次、独立票务时间线和来源证据。
- **我的 Pickup**：节目级想看名单，场次级购票状态；收藏本身不发送通知，明确启用后才发送。
- **日历**：演出与售票节点可分开查看；标记精度未知，不造假时间。
- **来源状态**：七家覆盖情况、已接入来日公演主办方、最后成功同步、已知盲区、待复核数量。

## 产品排除范围

- 不开发全球音乐家/乐团或全球作品目录，不做以单一作品为中心的主动推荐。
- 不新增明确排除的四家乐团（见 `00_DECISIONS.md`），不以全日本职业乐团数量作为首版指标。
- 不做自动买票/代抢、实时库存承诺、未授权邮箱读取、第三方票务账号密码保管。
- 不做首版人工“编辑精选”或音乐质量客观打分；可以有规则明确的精选模块作为后续。
- 爵士、摇滚后续迭代。

## 非功能要求

移动端优先、中文 UI 与日文原文共存、桌面响应式、可核对原始来源。发布时间和售票日期缺失显示未知；不因空字段而自动推断默认时刻。只有官方公告证实才把取消、改期标为已确认。遵守访问政策与素材许可。
