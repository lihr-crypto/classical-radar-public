# 09. 第三方 Review 处理记录

来源：用户提供的《Classical Radar 方案评估（v1.4 交接包）》，2026-10-31。以下是对 Review 的逐项决策；这些是需求取舍而非已验证技术事实。

| Review 议题 | 决策 | v1.5 落地方式 |
|---|---|---|
| 海外/独奏会验证被排在七团之后 | **采纳** | P0-A 与 P0-B 并行，先验证风险最大的两种演出；不能只先做七团网站 |
| 最新公布冷启动平局 | **采纳** | 官方公告日期优先；缺日期显示首次收录、区分初始导入；`sitemap lastmod` 不能充当首发日期 |
| 多份字段/API 名称漂移 | **采纳** | `03_CONTRACTS.md` 唯一权威；修复状态、时间精度、API 前缀、Pickup 层级 |
| 个人项目技术过度设计 | **部分采纳** | 普通分页、单用户、可选 Supabase、不强制复杂 outbox/RLS；但保留三层业务模型/身份验证/提醒去重 |
| 八样本声称95%准确率 | **采纳** | 8例是回归起点，不做统计结论；增加官方清单 n/N 覆盖、关键日期零伪造与持续时效监测 |
| 第三方线索不对用户展示 | **部分采纳** | 私用环境增加显著待核实层级；不能混入已确认主榜/开票提醒 |
| 国内乐团仅五家 | **采纳但按用户指定限制** | 增加读卖和东京爱乐，仅7家；用户明确排除的另外四团不纳入本版 |
| 半天人工 Spike | **采纳方向，不接受时长承诺** | 先人工检查页面/条款；程序化实测和连续追踪时间由结果决定 |
| 官方 URL 半自动导入 | **采纳为备用，不采纳替代自动发现** | 前置到 P0，作为难源的合法降级；用户最初需求仍是无需手动逐站搜索 |
| 先做七团 MVP，海外/独奏会往后 | **不采纳这个顺序** | 两边来源 POC 同级。可分批上线通过验证的来源，但不能在计划上继续延后海外风险验证 |
| 纯全文搜索替代作品结构化过滤 | **部分采纳** | 先轻量原文抽取+可核别名，全文兜底；结构化筛选仍在 MVP，避免建全球曲库 |
| 全量前端过滤、取消分页 | **不采纳** | 简单服务端分页即可；无需复杂 keyset cursor |
| 取消编辑精选 | **采纳** | v1 只保留“我的 Pickup”；无需长期人工策展 |
| 私人使用就能放心抓取 | **不采纳绝对化表述** | 仍逐站审查条款、robots、版权与再发布边界；私人不等于无风险 |

## Review 未充分提到的 P0 必验风险

- **来源内覆盖率**：解析的条目准确还不够，要对照同一区间官方公演列表计数 n/N，报告漏掉哪些。
- **跨来源盲区**：抓完 Japan Arts、KAJIMOTO 也无法证明覆盖了“日本所有海外名团”；必须公布已接入来源和限制。
- **时效性**：首次扫描无法验证能否及时发现追加销售、抽选截止变更；需要模拟差异 + 后续连续监控。
- **东京爱乐跨类型**：歌剧、芭蕾等协演需要清晰标注，不得自动当作常规交响音乐会。
