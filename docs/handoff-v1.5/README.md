# Classical Radar — Agent 交接包 v1.5

更新日期：2026-10-31。**尚未完成真实的程序化采集 POC；本交接包是计划，不是已运行的软件。**

## 产品目标

以已核实的**日本未来公演**为入口，发现首都圈七家优先乐团、海外名团来日公演和日本/海外钢琴家独奏会；在同一处完成多维筛选、我的 Pickup、售票时间线、日历和提醒。拒绝全球乐团/演奏家百科，不能用无日本公演的资料卡填充发现页。

## 此次决策摘要

- **国内重点乐团固定 7 家**：NHK交响乐团、东京都交响乐团、东京交响乐团、日本爱乐、新日本爱乐、读卖日本交响乐团、东京爱乐交响乐团。其余日本乐团不在本次开发范围。
- 数据源 POC 优先级调整：七团与海外/钢琴独奏会官方来源**并行验证**，海外来源不能被简单降为后期可选项。
- 默认发现偏好：全部 / 未来12个月 / 首都圈优先但全国可见 / 最新公布（无可靠发布日期显示“首次收录”）。
- **节目级 Pickup + 场次级购票管理 + 售票节点级提醒**；不是两套并行的收藏系统。收藏不代表开启通知。
- 只在已收录公演内提供作曲家/作品/指挥/演奏者的结构化筛选；允许以全文检索做初步降级，但不能从产品范围中删除结构化筛选。
- 采用轻量实现：API 简单页码分页，单用户优先；安全、可追溯、通知去重不可牺牲；取消首版人工维护的“编辑精选”，保留“我的 Pickup”。
- 第三方线索可在**明确标注的待核实区域**显示给私有工具用户，绝不与官方确认公演混排、触发定时开票提醒。
- 半自动官方 URL 导入前置为 P0 备用通路，但自动发现仍是主要产品价值。

## 阅读和规格优先级

1. `00_DECISIONS.md`：范围、默认行为和采纳/不采纳的决定，**唯一范围权威**。
2. `03_CONTRACTS.md`：数据库模型、名称、枚举、API，**唯一字段/API权威**。示例 JSON 与之对齐。
3. `01_PRD.md`：用户目标、页面、功能与非目标。
4. `02_SOURCES.md`：官网来源、审核和降级。
5. `04_ROADMAP.md`：执行顺序、门槛、交付任务。
6. `05_ACCEPTANCE.md`：证据、统计和关键回归测试。
7. `06_AGENT_INSTRUCTIONS.md`：**可直接粘贴给开发 Agent 的首轮任务**。
8. `07_UI_UX_DESIGN.md`：Apple Music 视觉、演奏会びより筛选与日历交互。
9. `08_MARKET_AND_OPEN_SOURCE.md`：市场产品、候选开源组件，非既定依赖。
10. `09_REVIEW_DECISIONS.md`：第三方评审逐条处理。
11. `examples/` 为纯虚构合约 fixture；`references/user-screenshots/` 为用户提供的参考截图，不能作为产品素材再发布。
