# 07. UI/UX 设计原则

## 设计参考与限制

- **Apple Music Concerts**：大型照片/视觉焦点、横滑精选、沉浸式详情、柔和渐变和清楚的信息层级；这里只借鉴设计语言，不复制界面或受保护的视觉素材。
- **演奏会びより**：作曲家、作品、指挥家/演奏者、乐团、音乐厅等筛选入口；详情的曲目和多场次结构；月/列表日历。
- **Classical Radar 差异化**：展现售票阶段与截止时间、演出确认状态、数据来源、个人 Pickup 与购票状态；不能让漂亮海报掩盖即将到期的抽选。

## 页面与移动端结构

1. **发现**：首屏紧凑待办（仅已开启通知/已 Pickup 的明确待办）、四项默认筛选胶囊；下方“首都圈”“日本其他地区”“海外名团”“钢琴独奏会”分组，支持切换按公演与按已有日本公演的乐团/钢琴家聚合。
2. **筛选**：类型、12/24个月、首都圈优先/全国、最新公布/演出日期/即将开票；进一步按作曲家、作品、指挥、演奏者、乐团、场馆组合。移动端抽屉、多选标签、一键清除；未识别原文可通过搜索匹配。
3. **详情**：有授权的图片或排版渐变艺术卡，标题/乐团/人员、曲目原文顺序、日语正式信息、相关场次、单场次不同票务阶段及源网址、Pickup/场次状态与提醒操作。所有缺失时刻明确“时间未公布”。
4. **日历**：演出/售票/全部切换，月和列表视图；同一天多件事可点入具体场次；仅日级信息显示为全天且带“具体时间待公布”。
5. **我的 Pickup**：展示节目级收藏；展开显示选择的场次与状态；提醒开关必须有清楚确认，不默认开启。
6. **来源状态**：当前七团接入进度、海外主办方覆盖、最后成功同步、缺失/待核实提示。

## 状态与风险可视化

- `已确认`：真实日本场次、官方来源；在发现主列表展示。
- `官宣·日期待定`：独立专题；不排入日期日历，不预设开票。
- `待核实线索`：独立可收起的区域；注明非官方验证、不能设正式售票提醒。
- `缺少官方首次发布日期`：卡片标签“首次收录”；**不得**用“最新官宣”标签。
- `售票中`：不等于实时有票；官方购票链接旁保留最后核验时间。
- 官网暂无照片或图片没有明确授权：使用原创图形/字体排版背景，不复制Apple、票务站或乐团宣传图。

## 视觉规格建议

- 文字：中文 UI + 日文原文、在音乐专名上可附经核实的别名；清晰区分事实与简介意见。
- 布局：手机底部4栏（发现/搜索/日历/我的），桌面左侧导航；列表模式紧凑、详情页留白适度。
- 系统深浅色；明暗对比充分；大点击区域；禁用仅靠颜色表达售票状态。
- 风格先做 2–3 个基于**真实数据**的高保真页面，再统一 token，不用虚构大量海报来掩盖数据缺失。
